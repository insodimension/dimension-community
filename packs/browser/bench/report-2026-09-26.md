# Browser plugin: end-to-end test and benchmark, 2026-09-26

The Browser plugin was tested two ways overnight:

1. **Benchmark.** A 14-stage practice world with each task agent: create a mail
   account, join the professional network, verify the email, complete the
   profile, then ten job applications. Each run was recorded.
2. **Live in Dimension Dev.** A fresh, isolated desktop: install from the
   marketplace, then give the chat agent a long job to do in the Browser View.
   Each session was recorded.

Videos are in `C:\Users\Sameer Pallav\Videos\dimension-browser-e2e-2026-09-26\`.
Each has a run timer, and the benchmark videos also show the current stage, a
stage timer and the agent's latest step.

## Models

Every model call went through Google Gemini (`gemini-3.1-flash-lite` for the
task agents, `gemini-3.8-flash` for the desktop chat agent). That was forced by
account balances, measured at 00:00 UTC:

- Command Code: 34.65 of 35 weekly credits used; requests return "insufficient credits".
- OpenCode Go and Zen, on both keys: "Insufficient account funds" / "An active OpenCode Go subscription is required".
- OpenAI: "You have no credits remaining".
- xAI: "used all available credits".

The earlier baselines used `xiaomi/mimo-v2.6-flash`. The model change and the
code changes below are separated where the data allows it.

- **Model change alone** (same code, library defaults): 3,031 s at 79% became
  725 s at 100%.
- **Flash mode alone** (same model, same concurrency): 23% less time and 3.1×
  fewer tokens, at the same 14/14.
- **Warm worker**: measured directly on the time to a browser-use task's first
  step, through the MCP server. Cold is 9.2–12.0 s; warm is 4.1–5.4 s (four

  without concurrent load, so that gain is not credited to the warm worker alone.

Per stage, jev is the fastest agent when it works: 3–16 s against browser-use's
10–46 s. It fails on six stages:

- mail: clicks Create before the robot check turns green;
- umbrella: `Emulation.setDeviceMetricsOverride timed out waiting for the daemon`;
- hooli, the Network job search, Cyberdyne and Tyrell: "could not make progress".

Hybrid was slower than browser-use alone tonight (762 s against 435 s). jev's
failed attempts cost time, and browser-use then takes longer on a page jev has
already touched: umbrella fails outright after jev, while it passes in 34 s
without jev. With browser-use in flash mode and a warm worker, **browser-use
alone is the best default**. jev is worth it only for simple single-page forms.

## What changed

### Engine (`insodimension/oh-my-pi`, branch `fix/marketplace-install-ignores-dev-deps`)

- `installCachedPluginDependencies` now installs against the manifest with its
  `devDependencies` removed, using `--omit=dev` (because `--production` freezes
  the lockfile), then restores the original bytes on success and on failure.
  This unblocks marketplace installs of Browser. PR Viewer, router-jev and
  artifactory-general-agent declare the same kind of devDependency.
- Tests: `bun test test/marketplace/cache.test.ts`: 30 pass, 50 `expect()`.
  Three new tests: a `workspace:*` devDependency, a failed install restoring
  the manifest bytes, and a shipped `bun.lock`. Each new test was run once
  against a mutated `cache.ts` and failed. `tsc --noEmit` exits 0.

### Browser pack (`insodimension/dimension-community`, branch `inso/feature/browser-e2e-overnight`, stacked on #109)

- **Warm task worker** (`src/task.ts`, `python/dim_browser_bridge/__main__.py`).
  Once a task has run, one worker stays pre-spawned with browser-use already
  imported. It is unref'd while idle, discarded if the environment changes, and
  exits after 10 minutes unused. A worker spawned for a job imports only what
  that job needs, so jev pays no browser-use import (its first step came at
  2.1–2.8 s).
- **browser-use in flash mode** without its planner or judge call (`browser_use_task.py`).
- **Delta frames.** `browser_frame` accepts `since=<frameId>`; a still page
  answers `{ unchanged: true }` with no pixels. The View's 10 Hz poll on a still
  Wikipedia article dropped from 2.0 MiB/s to 88 KiB/s (on example.com: 226 →
  16 KiB/s).
- **Benchmark:**
  - `--record` writes one video per agent.
  - `/__seed` repairs a failed account stage, so later stages measure their own
    task. Before this, jev scored 0/14 because its failed mail signup failed
    every later stage too. With it, the same agent scores 8/14.
  - Steps carry timestamps.
- Tests: `bun test test/` gives 51 pass, 0 fail. The `expect()` total varies
  between runs (208, 210, 212) because some tests assert inside loops that
  depend on timing; no test failed in any run. `tsc --noEmit` exits 0.

Both diffs had a fresh `reviewer` pass. All findings were applied: the
frozen-lockfile regression, spare-only preload, seed repairing wrong fields
rather than only missing ones, a guarded seed call, no phantom video entries,
and doc claims.

## Found, not fixed (for the owner)

- **Every View tool needs approval, and "Always allow" does not survive a
  restart.** A community pack's own app-only tools (`browser_profiles`,
  `browser_frame`, `browser_viewport`) each raise a blocking modal. While a
  modal waits, the View's frame poll times out and shows "Reconnecting to the
  browser… MCP error -32001". This is host policy (not a first-party app), but
  "Always allow" came back after a desktop relaunch.
- **The marketplace Install button gives no feedback for 20+ s.** All Install
  buttons go disabled with no spinner on the card being installed. A failure
  shows raw bun stderr.
- **Task agents after a marketplace install have no Python env.** This is by
  design ("opening a browser never installs anything"). The error message was
  enough for the agent to fix it on its own, but first use costs one failed call
  plus a `uv sync`.
- **jev-ultrafast (upstream):** sends a `reasoning` object that Gemini's
  OpenAI-compatible endpoint rejects, so the benchmark used a local relay that
  strips it; it gives up on the robot-check timing; and its daemon times out on
  `Emulation.setDeviceMetricsOverride` on umbrella.
- **The workspace popover in the thread header stayed open** over the chat for
  whole sessions in the desktop (visible in every desktop video).
